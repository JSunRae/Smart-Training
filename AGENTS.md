## Concurrent tasks and archives

Before changing files or provider resources, read `docs/tasks/README.md`, inspect `docs/tasks/active/`, and create or resume your own task record there. Record the task ID, agent/thread identity, exact file and provider-resource claims, status, heartbeat, authorization source, evidence, blockers, and next action. App thread activity is not a task claim. Preserve all existing work.

Use one task record per workstream; edit only your own record. Check claims again immediately before editing shared files or changing shared resources. Overlapping or uncertain ownership requires a recorded handoff before mutations; continue independent work while resolving it. A stale heartbeat does not release a claim. Serialize shared-checkout installs, builds, E2E servers, Git index operations, and provider deployments. Prefer a task worktree when isolation is needed; never assume uncommitted changes belong to you.

Update your record after material progress, before long operations, at least every 30 minutes during active work, and before ending a turn. Record blocked or deferred tasks accurately, without claiming completion. Archive completed or cancelled task records under `docs/tasks/archive/YYYY-MM/` with evidence and handoff notes; retain logs and release evidence. Do not archive another agent's task or delete its artifacts. The detailed procedure and copyable agent prompt are in `docs/tasks/README.md`.
